# TradingWave — API Contracts Specification
**Version:** 1.0.0  
**Base Path:** `/api/v1`  
**Protocol:** HTTPS / WSS  
**Data Format:** JSON (ISO 8601 UTC timestamps, decimals represented as numeric or string for exact precision)

---

## 1. General API Conventions

### 1.1 Headers
All requests should include:
- `Authorization: Bearer <session_jwt>` (for authenticated endpoints)
- `Content-Type: application/json`
- `X-Correlation-ID: <uuid>` (client-supplied or automatically generated by API middleware)

All responses will include:
- `X-Correlation-ID: <uuid>`
- `Content-Type: application/json; charset=utf-8`

### 1.2 Standard Response Envelope

#### Success Response Envelope
```json
{
  "data": { ... },
  "meta": {
    "request_id": "c1f8a84a-38bb-4b68-b710-8bfa0d2e8241",
    "timestamp": "2026-10-24T12:00:00.000Z",
    "pagination": {
      "page": 1,
      "page_size": 20,
      "total_items": 42,
      "total_pages": 3
    }
  }
}
```

#### Standard Error Response Envelope
```json
{
  "error": {
    "code": "STRATEGY_VALIDATION_FAILED",
    "message": "The provided strategy specification failed deterministic validation.",
    "request_id": "c1f8a84a-38bb-4b68-b710-8bfa0d2e8241",
    "details": [
      {
        "field": "entry_conditions.all[0].left",
        "reason": "Unknown indicator reference 'fast_ema_2'. Available indicators: ['fast_ema', 'slow_ema', 'rsi']."
      }
    ]
  }
}
```

### 1.3 Standard Error Codes
| HTTP Status | Error Code | Description |
| :--- | :--- | :--- |
| `400` | `INVALID_REQUEST_BODY` | Request body failed Pydantic schema validation. |
| `400` | `STRATEGY_VALIDATION_FAILED` | Strategy AST validation, cycle check, or parameter range check failed. |
| `401` | `UNAUTHENTICATED` | Missing or expired authentication token. |
| `403` | `WORKSPACE_ACCESS_DENIED` | User is not a member of the requested workspace. |
| `403` | `COMPLIANCE_GATE_BLOCKED` | Live execution attempted without required SEBI/exchange certified approvals. |
| `404` | `RESOURCE_NOT_FOUND` | Specified resource ID was not found in the tenant's workspace. |
| `409` | `RESOURCE_CONFLICT` | Resource already exists (e.g. duplicate client order ID, duplicate version). |
| `422` | `UNPROCESSABLE_ENTITY` | Semantic business rule violation. |
| `429` | `RATE_LIMIT_EXCEEDED` | Request quota exceeded for AI drafting or backtest submission. |
| `501` | `FEATURE_NOT_ENABLED` | Feature (e.g., live broker order) is disabled by system policy. |

## 2. API Endpoints

### 2.1 System Health
- **`GET /api/v1/health`**  
  Liveness probe. Returns 200 OK if FastAPI process is alive.
- **`GET /api/v1/health/ready`**  
  Readiness probe. Checks PostgreSQL connectivity, Redis ping, and storage accessibility.

---

### 2.2 Authentication & User Context
- **`POST /api/v1/auth/session`**  
  Authenticate credentials and establish a secure session. Returns user info and JWT token.
- **`DELETE /api/v1/auth/session`**  
  Terminate the current session and invalidate tokens in Redis.
- **`GET /api/v1/users/me`**  
  Get details of the currently authenticated user and their active workspaces.

---

### 2.3 Strategies & Versions
- **`POST /api/v1/strategies`**  
  Create a new draft strategy container within the active workspace.
  - Body: `{ "name": "Nifty EMA Breakout", "description": "5m Intraday EMA strategy" }`
- **`GET /api/v1/strategies`**  
  List strategies in current workspace with search, filter, and pagination.
- **`GET /api/v1/strategies/{strategy_id}`**  
  Retrieve strategy metadata and current active version specification.
- **`PATCH /api/v1/strategies/{strategy_id}`**  
  Update strategy metadata (name, description, status: `draft`, `published`, `archived`).
- **`POST /api/v1/strategies/validate`**  
  Deterministic validation endpoint. Accepts full strategy specification JSON, runs static compiler checks, graph connectivity, cycle detection, and parameter boundary verification. Returns validation errors or compiled canonical AST and specification hash.
- **`POST /api/v1/strategies/{strategy_id}/versions`**  
  Publish a new immutable version.
  - Body: `{ "specification": { ... } }`
  - Validates specification, calculates canonical SHA-256 hash, increments `version_number`, and persists immutable record.
- **`GET /api/v1/strategies/{strategy_id}/versions`**  
  List all published historical versions of a strategy.
- **`GET /api/v1/strategies/{strategy_id}/versions/{version_id}`**  
  Retrieve exact specification for a published version.

### 2.4 AI Strategy Studio
- **`POST /api/v1/ai/strategy-drafts`**  
  Convert a natural-language description into a structured draft specification.
  - Body:
    ```json
    {
      "prompt": "Buy NIFTY 50 when 9 EMA crosses 21 EMA from below on 5-minute bars and RSI is above 55. Exit when 9 EMA crosses below 21 EMA. Stop loss 1.5%, take profit 3%.",
      "instrument_preference": { "exchange": "NSE", "symbol": "NIFTY50" }
    }
    ```
  - Response:
    ```json
    {
      "data": {
        "status": "draft",
        "strategy_specification": { ... },
        "clarification_questions": [
          "Should intraday positions be squared off before 15:15 IST?"
        ],
        "validation_result": { "is_valid": true, "warnings": [] },
        "suggested_tests": [
          "Test 9 EMA crossover with RSI = 60 triggers Buy signal",
          "Test 9 EMA crossover with RSI = 48 triggers No signal"
        ]
      }
    }
    ```
- **`POST /api/v1/ai/explain`**  
  Provide natural-language explanation of strategy logic, condition rules, or backtest anomalies.

### 2.5 Backtesting Lab
- **`POST /api/v1/backtests`**  
  Enqueue an asynchronous backtest job.
  - Body:
    ```json
    {
      "strategy_version_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
      "dataset_id": "e4b6c31a-7b3d-4c8d-8a5e-1a2b3c4d5e6f",
      "configuration": {
        "initial_capital": 500000.0,
        "slippage_bps": 5.0,
        "cost_model": "indian_statutory_standard",
        "lot_size": 25,
        "date_range": {
          "start_date": "2023-01-01T09:15:00Z",
          "end_date": "2023-12-31T15:30:00Z"
        }
      }
    }
    ```
  - Response: `202 Accepted` with `{ "data": { "job_id": "...", "status": "QUEUED" } }`
- **`GET /api/v1/backtests/{job_id}`**  
  Poll job status (`QUEUED`, `RUNNING`, `COMPLETED`, `FAILED`, `CANCELLED`).
- **`GET /api/v1/backtests/{job_id}/results`**  
  Retrieve summary statistics, performance metrics (Sharpe, Sortino, Max Drawdown, Win Rate, Profit Factor, Indian statutory cost breakdown), and URIs for detailed curve/trade artifacts.
- **`GET /api/v1/backtests/{job_id}/trades`**  
  Paginated trade log including bar timestamp, entry price, exit price, duration, slippage incurred, statutory taxes paid, and net return.
- **`POST /api/v1/backtests/{job_id}/cancel`**  
  Cancel an active or pending backtest job.

---

### 2.6 Paper Trading
- **`POST /api/v1/paper-sessions`**  
  Start a simulated trading session against market data replay or virtual feed.
- **`GET /api/v1/paper-sessions`**  
  List paper sessions in current workspace.
- **`GET /api/v1/paper-sessions/{session_id}`**  
  Get live telemetry, simulated cash balance, unrealized P&L, and open positions.
- **`POST /api/v1/paper-sessions/{session_id}/stop`**  
  Gracefully stop paper simulation and close virtual session.
- **`GET /api/v1/paper-sessions/{session_id}/orders`**  
  List simulated virtual orders and execution states (`CREATED`, `ACCEPTED`, `FILLED`, `REJECTED`, `CANCELLED`).
- **`GET /api/v1/paper-sessions/{session_id}/positions`**  
  Retrieve active virtual positions and average cost basis.

### 2.7 Broker Connections & Live Execution (Strictly Gated)
- **`POST /api/v1/broker-connections`**
- **`GET /api/v1/broker-connections`**
- **`POST /api/v1/deployments`**
- **`GET /api/v1/deployments/{id}/status`**
- **`POST /api/v1/deployments/{id}/stop`**

*Enforcement Note:* When `LIVE_TRADING_ENABLED=false`, all live execution endpoints immediately respond with HTTP `403 Forbidden` or `501 Not Implemented` accompanied by the `COMPLIANCE_GATE_BLOCKED` error code.
